  The renderer must OR `AppInfo.reducedMotion` with `matchMedia('(prefers-reduced-motion: reduce)')`.
- desktop-release.yml merges assets of both Linux arches into one folder: electron-builder writes `latest-linux.yml`
  (x64) and `latest-linux-arm64.yml` (arm64), so they do not collide, but the workflow has never run.
- desktop-release.yml moves the rolling `desktop-latest` tag with `git tag -f` + `git push -f origin desktop-latest`
  (a moving tag needs a forced tag push; it only touches that tag and the orphan `desktop-release` branch).
  The owner should confirm that is acceptable under the repo's no-force-push rule before enabling it.
- CI/release build native arch per runner (`--$(node -p process.arch)`); macOS builds x64+arm64 on one runner.

  notarisation env (APPLE_ID etc.) is not set up. Unsigned mac builds will not auto-update on macOS.

## Contract change requests
- `Bridge.keys` has no setter for `storeInactive` (the opt-in to keep inactive keys with obfuscated storage when no
  keyring exists). The vault supports it (`File.storeInactive`), `KeyStorageInfo.storeInactive` reports it, but the
  renderer cannot change it. Suggest `keys.setStoreInactive(on: boolean): Promise<Result<KeyStorageInfo>>` (or a
  Settings key `keysStoreInactive`).
- e2e/fixtures.ts `LaunchOpts` gained an optional `env?: Record<string,string>` (extra launch env). Backward compatible;
  PLAN 7.5 could list it.

## Known bugs / caveats
- `findFreePort` binds 127.0.0.1 briefly to pick a port when another install owns the configured one (race window
  before serve binds it). A start that fails with "address already in use" ends in phase `down` with problem
  `port-in-use`; it is not retried automatically (the Retry action starts again). Only a serve that dies after
  coming up is respawned (1/5/15 s, max 3 in 5 min).
- In attach-only mode with the backend down, the manager re-probes /healthz every 2 s (cheap, but forever).
- pty.spec uses /tmp as the terminal cwd.
- The renderer build (other legs) still had type errors at handover time; build.mjs only warns for it in dev.
