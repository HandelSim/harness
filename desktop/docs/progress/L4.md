### Architecture (files)
- **`index.ts`**: public API. Exports `createBackground`, `DEFAULT_BG`, `CATALOG` and `normalizeConfig`.
- **`engine.ts`** (main thread, `BgEngine` implementation):
  - One layer per config, cross-faded.
  - CSS layers handle solid, mesh and grid. Drift uses the Web Animations API and is paused with the engine.
  - Dynamic layers use a canvas with `transferControlToOffscreen` and the module worker.
  - Fallback ladder:
    1. Worker WebGL2.
    2. Worker 2D. A per-id GL block applies (for example, grayscott without float FBOs). A global GPU-broken flag is set on "webgl2 unavailable", or on 2 context losses within 60 s.
    3. `MainRunner` (main-thread 2D at 15 fps). Used when the worker breaks.
    4. CSS static. Used on a 2D failure or when the governor reaches tier 3.
  - Pauses on `document.hidden`.
  - Thumbnails go to the worker, which falls back to the main thread. They are cached by `id|wxh|theme`.
  - Non-contract hooks:
    - `engine.debugBurn(ms)`
    - `#bg-root[data-bg-frames|data-bg-renderer|data-bg-id]`, used by the e2e tests and the demo.
- **`worker.ts`**: validates every message (`protocol.ts`), keeps scenes by layer id, posts `ready`, `stats`, `fail` and `thumb`.
- **`host.ts`** (`Scene`):
  - Fixed 1/60 timestep, clamped dt, at most 6 steps per frame.
  - fps = min(cfg cap, governor rung, dim 15, main 15).
  - Budget is 4 ms of CPU per frame.
  - GL context loss and restore.
  - `pause` stops the loop (zero frames, zero timers).
  - Reduced motion produces one coalesced settled frame (a 40 ms debounce over the init, state, theme and resize burst).
  - A downgrade is reported at once.
- **Pure modules**: `governor.ts`, `prng.ts`, `noise.ts`, `palette.ts`, `catalog.ts`, `protocol.ts`. `noise.ts` uses simplex-noise 4.0.3 plus its own value noise, fBm and curl.
- **`effects/*`** (all tunable by intensity, speed and seed):

  | Effect | Implementation | Render scale |
  |---|---|---|
  | `silk` | GL fBm domain warp; a 2D fallback exists | 0.35 |
  | `aurora` | GL only | 0.25 |
  | `flow` | Curl noise; CPU intensity buffer with one `putImageData` per frame | 0.5 |
  | `attractor` | Clifford / de Jong log-density histogram. Morphs between verified waypoints near the preset and holds the image while the orbit sits in a periodic window | 0.5 |
  | `tracers` | RK4 3D systems with slow yaw and perspective | 0.5 |
  | `grayscott` | GL RG16F ping-pong at 256 sim; a CPU 2D fallback exists | — |
  | `life` | B3/S23 on a torus with ghost trails | — |

  `gl/program.ts` holds the shared fullscreen triangle and GLSL noise; `gl/fbo.ts` holds the ping-pong buffers.
- **`thumb.ts`**: renders a settled frame at 3x into a scratch OffscreenCanvas, downsamples it into a w×h OffscreenCanvas, then calls `convertToBlob`.
- **`demo.html` / `demo.ts`** (dev build only, `out/renderer/bg-demo.html`):
  - Controls for every config field, theme, run state, reduced motion and burn.
  - Shows live stats, a thumbnail grid and a cycle button.
  - Query params: `id, theme, seed, reduced, state, cycle, thumbs=0`.

### Fixed during this session (found by screenshots)
- **attractor**:
  - The bug: morphing 35% toward the next preset collapsed most orbits onto a fixed point, so the screen showed one dot.
  - Now it morphs between waypoints near the preset whose paths are checked to be chaotic. A runtime guard holds the image while the parameters are in a periodic window.
  - Regression tests have been added.
- **flow**: fixed two problems.
  - Only the last fixed step of a multi-step frame was stroked.
  - Thousands of alpha path strokes were raster-bound on software GL, giving about 7 fps.
  - It now uses a CPU intensity buffer.
- **aurora**: rays used 5-octave fBm at high frequency, which aliased into hard stripes at a 0.25 scale. It now uses two low octaves.
- **mesh**: the blooms were nearly invisible. Their colours are brighter now and the vignette is lighter.

## Known issues / risks (priority order)
1. **Perf on this host (no GPU)**:
   - Main-thread rAF p95 in ms, measured over 2.5 s per id. The `solid` CSS baseline is 16.8 ms. The numbers are noisy, because other legs were building at the same time.

     | Run | Load | solid | silk | aurora | flow | attractor | tracers | grayscott | life |
     |---|---|---|---|---|---|---|---|---|---|
     | 07:17 | ~4.8 | 16.8 | 33 | 17 | **650** | 33 | 100 | 83 | 17 |
     | 07:19 | ~6.4 | 16.8 | 83 | 83 | **50** | 33 | 217 | 217 | 50 |
     | 07:20 | ~6.0 | 16.8 | 100 | 33 | **33** | 50 | 300 | 133 | 17 |

   - The 07:17 flow figure is from the old path-stroke version. The 07:19 and 07:20 flow figures are from the CPU intensity buffer version.
   - The new flow is also checked visually (`bg-shots/flow*.png`, re-shot at 07:21). It runs at 30 fps in the worker, about 6.6 ms per frame, so it may step to tier 1 under load.
   - On SwiftShader, GL and canvas raster run on the CPU in the GPU process, which starves the compositor. Moving work to the worker does not help with that.
   - The PLAN target (p95 < 25 ms "on this host") is **not met** for the GL effects and tracers.
   - Options:
     - Make the effect the user can pick depend on GPU availability: if `chrome://gpu` reports software, or a cheap GL probe is slow, default to CSS and mark heavy ids.
     - Have the governor also watch main-thread rAF jank (the engine can measure it), not only worker CPU time.
     - Draw tracers into a CPU buffer as flow now does.
   - The perf spec asserts the target only with `HARNESS_DESKTOP_E2E_PERF=1`. Run it that way on a host with a real GPU before calling 7.4 met.
2. **The governor measures worker CPU time only**: GL frames report ~0.05 ms because GPU time is invisible to it. It cannot detect GPU-bound or raster-bound load. Fix: EXT_disjoint_timer_query_webgl2 where available, and/or main-thread jank feedback as in (1).
3. **Thumbnails are slow on SwiftShader**: about 30 s for all 10 under load, because settle runs at 3x size. Reduce the oversample to 2x, and settle fewer steps for thumbnails.
4. **attractor on this host** runs at about 6 ms per frame at 0.5 scale, so the governor steps it to tier 1 (scale 0.35). The draw loop computes `log` for every pixel. A LUT or a lower default scale would avoid the step-down.
5. **Worker heap**: the 20 s heap check covers the page only. Dedicated workers do not expose `performance.memory`; measuring the worker heap needs a CDP worker session.
6. **aurora is GL-only**: without GL it falls to CSS static rather than a 2D look.
7. **Non-contract hooks** that L3 should not depend on: `engine.debugBurn(ms)` and the `data-bg-*` dataset attributes. They are used only by e2e and the demo.
