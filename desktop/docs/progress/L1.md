1. `TicketSummary.status` / `TicketState.status` can be `""`: a ticket folder whose state.json is missing or not a
   JSON object (Runs.ticket_state returns `{}`). Suggest `status: TicketStatus | ''`. Its gates are all off except
   `remove`, each with the reason "its state.json is missing or unreadable".
2. Extra keys the UI may want typed (all present now): `TicketSummary.{why, stages, in_place, plan_review, stuck}`,
   `Ticket.{why, retry_why, edit_lock: [can, why], continue_mode}`, `Queue.modes: ['container','host','single']`,
   `SettingsData.{config_error, allowlist_error, mcp_error}` and `access.me`, `Vaults.dir`, `vaults[].cloned`,
   `Home.pages[].{mtime, url}`, `VaultOverview.pages[].mtime`, `Status` none.
3. Untyped endpoint shapes (no type in api.ts): `/tickets/<K>/edit` -> `{form: {field: value | [values]}, can, why}`;
   `/queue/runner-log` -> `{text}`; `/follow` -> `{sid: string | null}`; `/sessions/<sid>/parts/<pid>` and
   `/findings/notes/..` and `/debug/<kind>/<name>` -> `{text}`; `/settings/doctor` -> `{rc, text}`;
   `/vault/tree` -> `{entries: [{name, path, dir, size}]}`; `/vault/file` -> `{path, kind: 'markdown'|'text'|'image',
   text, truncated?, url?}`; `/sessions/<sid>/export` -> runs.export's dict (pass-through).
4. `Runner.watch` is sent as a boolean (serve's "unknown" None becomes false), `beat` is 0 (not null) with no
   heartbeat, `parallel` is 0 (not 1) for a single run. The L2 mock (`scenarios.mjs`) uses `beat: null`,
   `parallel: 1`: harmless if the UI only tests truthiness / `> 1`.
5. `TicketState.history[].at` and `notes[].at` are ISO strings as stored (the L2 mock uses epoch ms numbers);
   session times are epoch ms. The UI should parse both.

## Known bugs / caveats
- `VaultOverview.facts.head[1]` and `log[].when` are git's relative times ("5 minutes ago"), so the vault topic's
  sig changes when that text does (at most once a minute; no worse than the web page).
- A ticket's `retry_choices` are worked out in the background (git): the first read after a change may list every
  stage, and the next poll brings the queue's real answer (same as the web page; the sig changes once).
- `stuck` (stopping for longer than STUCK_AFTER) flips once, changing the sig once.
