# External Integrations

**Analysis Date:** 2026-06-02

## APIs & External Services

**Upstream LLM API (required):**
- Gemini Enterprise — the third-party chat API the proxy translates for; identified as a Gemini Enterprise product exposed behind an OpenAI chat-completions-shaped HTTP interface (see `architecture/upstream-api.md`)
  - SDK/Client: `requests` library in `proxy/proxy.py` — raw HTTP POST, no vendor SDK
  - Auth: `PROXY_API_KEY` (Bearer token injected as `Authorization: Bearer <key>` header); `PROXY_API_URL` (base URL)
  - Endpoints used: `{PROXY_API_URL}/v1/chat/completions` (POST, chat), `{PROXY_API_URL}/v1/models` (GET, model catalog)
  - Key lifecycle: keys lock every ~8 hours; unlock requires visiting a browser URL. Keys expire after ~1 month. Unlock URL surfaced in 401 response body (`error.unlock_url`). See `architecture/upstream-api.md` for full lifecycle detail.
  - TLS note: `verify=False` in all requests (upstream uses a self-signed cert); `InsecureRequestWarning` suppressed at module load (`proxy/proxy.py` line 38–41)

**Exa web-search MCP (optional, firewall-conditional):**
- Exa — provides opencode's `websearch` tool via a hosted MCP at `mcp.exa.ai`
  - Activated by `OPENCODE_ENABLE_EXA=1` in the agent entrypoint (`agents/entrypoint.sh`)
  - With firewall UP: always exported; TCP REJECT is instant so failure is fast and harmless
  - With firewall DOWN (`--net`): only exported after a `curl --connect-timeout 1` probe to `https://mcp.exa.ai/mcp` succeeds (prevents TUI hang on slow/sick Exa endpoint)
  - Not configured in `docker-compose.yml`; wired exclusively through opencode's built-in MCP client

**GitHub API (firewall initialization only):**
- Used during container startup by `firewall/init-firewall.sh` to fetch GitHub IP ranges for the ipset allow-list
  - Endpoint: `https://api.github.com/meta` (GET, no auth)
  - Best-effort: failure is logged as WARN, not fatal; per-host DNS resolution covers `github.com` hostnames

## Data Storage

**Databases:**
- None — no application database. No ORM or DB client in any service.

**Persistent volumes (Docker bind mounts):**
- `./state/ollama-data` → `/root/.ollama` in the `ollama` container — stores ollama model blob store across container rebuilds (`docker-compose.yml`)
- `./state/output` → `/output` in the `proxy` container — proxy debug dump files when `OUTPUT_DIR` is set (`docker-compose.yml`)
- `./state/agent/home` → `/home/harness` in each agent container — shared, persistent home directory across all agent invocations; seeded from `/etc/skel/harness` on first run (`agents/entrypoint.sh`)
- `./state/mcp/serena/data` → `/root/.serena` in the `serena` container — per-install Serena index cache and project-list state (`mcp-registry/serena/compose.yml`)
- `${HARNESS_PROJECTS_ROOT}` → `/workspaces/projects:ro` in the `serena` container — user's project root, read-only (`mcp-registry/serena/compose.yml`)

**File Storage:**
- Local filesystem only. All state is in `<install-root>/state/` (gitignored). No remote object storage.

**Caching:**
- None — proxy does not cache upstream responses. ollama's blob store (`state/ollama-data/`) caches model weights locally.

## Authentication & Identity

**Upstream API auth:**
- Bearer token (`PROXY_API_KEY`) injected by the proxy on every upstream request (`proxy/proxy.py` `catch_all` handler)
- No OAuth, no session management; key is a static secret in `.env`

**Agent container user identity:**
- Agents start as root, then UID/GID remap to match the host caller (`HOST_UID`/`HOST_GID` env vars) via `usermod`/`groupmod`, then `gosu harness` drops privileges before any agent code runs (`agents/entrypoint.sh`)
- Git push protection: `configure-git-credentials.sh` sets `credential.helper=/bin/false` globally and configures `store` helper only for hosts annotated `# git-push` in `.harness-allowlist` (`firewall/configure-git-credentials.sh`)
- `GIT_TERMINAL_PROMPT=0` and `GIT_ASKPASS=/bin/false` are set in the agent image to prevent interactive credential prompts (`agents/Dockerfile`)

**opencode provider auth:**
- opencode connects to ollama via the `@ai-sdk/openai-compatible` provider with `apiKey: "harness-dummy"` — a placeholder key (ollama has no auth requirement). Set in `~/.config/opencode/opencode.json`, generated by `ensure_opencode_config` in `agents/entrypoint.sh`.

## Monitoring & Observability

**Error Tracking:**
- None — no Sentry, Datadog, or equivalent.

**Logs:**
- All services log to stdout/stderr (Docker container logs); no log aggregation service.
- Proxy logs each request with a timestamp-based `req_id` prefix: method, path, model, message count, tool count, upstream status, NDJSON emission (`proxy/proxy.py`)
- Debug file dumps: when `OUTPUT_DIR` is set, the proxy writes four JSON files per request (Ollama_Request, API_Request, API_Response, NDJSON_Response) to `state/output/` — opt-in only (`proxy/proxy.py` `save_debug_file`)
- Firewall logs startup events and IP resolution counts to stdout with `[harness-firewall]` prefix (`firewall/init-firewall.sh`)
- Ollama entrypoint logs model discovery and stub registration to stdout (`ollama/entrypoint.sh`)

## CI/CD & Deployment

**Hosting:**
- Self-hosted — harness runs on the user's own machine; no cloud deployment target.

**CI Pipeline:**
- GitHub Actions (`.github/workflows/ci.yml`)
  - `lint` job: `bash -n` syntax check on all shell scripts, `scripts/check_runtime_calls.sh` (no raw `docker` calls), advisory `shellcheck`
  - `unit` job: `bash ./harness test unit` — docker-free unit tests (`tests/unit_*_test.sh`, `tests/upgrade_test.sh`)
  - `docker-tests` matrix: `harness_test`, `proxy_test`, `persistence_test`, `mcp_test`, `firewall_test` — full docker tests with Buildx layer caching
  - `pipeline` job: `tests/full_pipeline_test.sh` — end-to-end test against mock upstream
  - Runners: `ubuntu-latest`; Docker data-root relocated to `/mnt` (66 GB) to avoid disk exhaustion during Buildx
- Anthropic Claude agent actions (`.github/workflows/claude.yml`, `.github/workflows/claude-code-review.yml`) — automated PR/issue handling; triggers on `@claude` mentions from `HandelSim`

**Secrets (CI):**
- No upstream API key needed in CI — CI tests use the mock API (`tests/benchmarks/mock-api/app.py`) or mock fixture responses (`tests/fixtures/responses/`)

## Webhooks & Callbacks

**Incoming:**
- GitHub Actions webhook — triggers the `claude.yml` workflow on issue comments and PR review comments containing `@claude`

**Outgoing:**
- None configured in application code. The proxy only makes synchronous HTTP requests to the upstream API; no webhook or async callback pattern.

## Container Services (Internal)

**harness-net bridge network:**
- All services communicate over a single user-defined bridge network `harness-net` (`docker-compose.yml`)
- Service discovery by DNS name: `ollama` (port 11434), `proxy` (port `$PROXY_PORT`, default 8000), `serena` (port 9121, when MCP enabled)
- Agent containers join the same network for the duration of a `docker run` invocation

**MCP services (optional, registry-managed):**
- Serena — semantic code analysis MCP server (SSE transport at `http://serena:9121/sse`)
  - Image: built locally from a git clone of `https://github.com/oraios/serena.git` at tag `v1.3.0` (`mcp-registry/serena/harness-meta.json.template`)
  - Installed via `harness mcp install serena`; enabled by presence of `state/mcp/serena/compose.yml`
  - Client config injected into opencode at agent launch via `merge_opencode_mcp_servers` in `agents/entrypoint.sh`

## Environment Configuration

**Required env vars (must be set in `.env` before first run):**
- `PROXY_API_URL` — base URL of upstream LLM API
- `PROXY_API_KEY` — upstream API bearer token (sensitive; never commit)
- `DEFAULT_MODEL_NAME` — upstream model id to use as default/fallback

**Optional env vars with defaults:**
- `PROXY_PORT` (8000), `PROXY_HOST` (0.0.0.0), `PROXY_TIMEOUT` (180s)
- `OLLAMA_VERSION` (0.21.2), `OLLAMA_CONTEXT_LENGTH` (200000)
- `OUTPUT_DIR` (empty — disables debug dumps)
- `HARNESS_CONTAINER_RUNTIME` (empty — auto-detects docker/podman)
- `HARNESS_EXTRA_MOUNTS`, `HARNESS_PROJECTS_ROOT`, `SERENA_DASHBOARD_PORT`
- `HTTP_PROXY`, `HTTPS_PROXY` — corporate proxy for host-side git and docker build (NOT injected into containers)

**Secrets location:**
- `.env` at `<install-root>/` (gitignored); contains `PROXY_API_KEY` and optionally proxy credentials
- No secrets manager, no vault; static file on disk
